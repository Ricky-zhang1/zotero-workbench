# 总体设计 · 第一性原理版

状态：自 0.6.0 起生效。本文是工作台的唯一设计依据；其他文档与本文冲突时，以本文为准。
定位：Codex 侧栏内的人机共用 Zotero 工作台。它不是通用文献管理器，不替代 Zotero 或 Lattics。

## 1. 设计目标

1. 学术研究者在 Codex 内完成「选文献 → 读原文 → 做标记 → 核论断 → 引用写作」完整循环；人可以直接操作，Agent 执行同一套操作。
2. 一切文献数据以本机 Zotero 为唯一真值；工作台不建第二个文献数据库。
3. 任何写入可预览、可授权、可回读、可追溯；结果不明时绝不盲目重试。
4. 行为在 Zotero 9/10 差异、外部服务额度变化、断线等真实条件下可预期、可解释。

## 2. 不可妥协的约束（是事实，不是选择）

| 约束 | 事实 | 设计影响 |
| --- | --- | --- |
| 真值库 | Zotero 拥有 items / attachments / annotations / notes | 工作台只做视图与受控写代理 |
| Zotero 9 本地 API 只读 | 写探测：支持写入的版本对空写入返回 428/401/412；9.0.6 实测返回其他状态 | 普通高亮写入需要 Zotero 10；写入前必须做能力检查 |
| Zotero MCP 插件（23120） | 有 write_note / write_item / write_metadata / create_review_highlight（审计高亮）；没有普通批注写接口 | 笔记、元数据、导入走插件；普通高亮走本地 API |
| 上游 ZCode 包 | 编译产物，MIT，SHA-256 固定，构建时按唯一锚点补丁 | 自有逻辑全部放在自有模块；升级须重验锚点 |
| Codex MCP Apps | app-only 工具对模型不可见 | 面板专属操作注册为 app-only，天然与 Agent 隔离 |
| 学术成本 | 引用错误代价高 | AI 证据高亮必须走 zotero-lattics 审计；颜色、相似度、旧高亮都不构成证据 |
| 界面风格 | 用户明确要求简约现代（2026-10-28，否决装饰性方案） | 界面层跟随上游 --z-* 主题变量；禁止自定义色相、装饰字体、印章/纹理与入场动效；只做间距、对齐、层级与数据可读性收敛 |

## 3. 第一性原理（七条）

- **P1 单一真值**：Zotero 拥有数据。工作台的任何缓存都可丢弃、任何视图都可从真值重建；导出永远携带可回链的 Zotero 身份。
- **P2 能力路由，而非功能直连**：写操作经由唯一写入网关，网关按「操作类型 × 通道能力」选择后端；新增通道只改网关，不改各功能。
- **P3 一切写入皆事务**：预览 → 授权 → 保留 → 提交 → 回读 → 台账。保留先于写入落盘；响应丢失留下 outcome-unknown 记录，禁止自动重试；成功区分「上游回执」「回读核实」「用户确认」三档。
- **P4 证据谱系完整**：凡进入写作的引文，携带 item key、attachment key、annotation key、物理页、批注页标、PDF SHA-256 与来源（用户直建 / AI 证据经审计）。批注不自动等于论断成立。
- **P5 人机同面**：每个能力只有一个接口；面板与 Agent 的差别只是工具可见性（app-only / model-visible）。不出现「只有界面能做」或「只有 Agent 能做」的暗功能。
- **P6 显式失败**：读取失败必须报错，禁止把失败渲染成零值或空成功；读取中文库变化必须丢弃结果；错误消息告诉用户下一步（例如「升级 Zotero 10」），不诱导重试。
- **P7 固定平台、自有适配**：上游包固定版本加校验和；所有业务逻辑在自有模块，锚点补丁只做接线。禁止把补丁逻辑越写越厚。

## 4. 领域模型

实体：Library · Item · Attachment(PDF, sha256) · Annotation · Note · Collection · Tag · CitationKey。

批注来源（origin）状态机：

- `user`：用户在阅读器亲自创建。用户即作者，直接写入；写入前做指纹去重。
- `agent-evidence`：Agent 为具体论断提出。必须完成 zotero-lattics 审计链（issue → preflight-bind → dryRun → 用户授权 → 写入 → 回读）才能进入文库。

操作四分类，各自的安全要求：

| 分类 | 例子 | 要求 |
| --- | --- | --- |
| 只读 | 浏览、读 PDF、证据采集、检索 | 分页完备、版本检测、显式错误 |
| 用户写入 | 个人高亮、阅读笔记、元数据修改、导入 | 预览或用户即时动作授权；写入网关；回读；指纹去重（高亮） |
| AI 证据写入 | 待核查证据高亮 | 完整审计链 + 明确 confirmWrite |
| 导出 | 引用、书目、文献卡片 | 无副作用；不夹带私人笔记；保留身份与状态标注 |

## 5. 分层与模块（目标形态）

```text
src/
  server.mjs            组合根：只做装配与注册（目标 ≤200 行）
  transports/
    zotero-local.mjs    本地 API 客户端：读 + 写探测 + 写入（Zotero 10）
    zotero-mcp.mjs      HTTP MCP 客户端（现 RickyClient）
  domain/
    library.mjs         分页完备性、累计缓存、版本检测
    gateway.mjs         写入网关：能力表 + 路由 + 统一事务
    evidence.mjs        证据采集、谱系、审计链接入
    citations.mjs       引用与书目导出（去私人字段）
    workspace.mjs       模板、文献卡片、信息检查
    duplicates.mjs      只读重复候选、字段比较、分页版本检查
  ui/                   面板源码（panel-*.js/css）与构建锚点
  tests/                四层测试（见 §11）
```

现状差距（0.7.0 时点）：transports/ 与 domain/ 已落地，两处事务实例已合并为单一网关（LibraryActions 接收共享 ReviewTransactions），面板源码独立于 src/ui/。剩余差距：server.mjs（268 行）仍内联约 18 个工具处理器体与网关装配，目标 ≤200 行；统一事务台账的写路径全部接入网关后，server.mjs 退化为组合根。按 §13 P0 继续，机械搬移，不改行为。

## 6. 写入网关（核心）

接口：`capabilities()` / `plan(op)` / `commit(plan)`。

路由表（当前事实）：

| 操作 | 通道 | 条件 |
| --- | --- | --- |
| 阅读笔记、元数据、单条条目导入 | 优先 Zotero 本地 API；明确只读的旧版可使用既有 MCP | 预览时固定通道、Server ID 与版本；写入失败不换通道重发 |
| 普通高亮 | 本地 API | Zotero 10（本地 API 可写） |
| AI 证据高亮 | Zotero MCP 插件 create_review_highlight | 审计链 + confirmWrite |

失败语义（全通道统一）：

- `verified`：上游回执且回读核实。
- `acknowledged`：上游回执，回读未完成或不适用——如实标注，不得宣称已核实。
- `outcome-unknown`：保留操作编号，禁止自动重试；先回读 Zotero。

幂等保护：用户高亮写入前按「附件 + 物理页 + 归一化文本」指纹查重；命中返回既有批注（`existing: true`），既防止响应丢失后的重试产生重复，也避免用户无意重复标注。元数据与导入用版本检查与 DOI 查重达到同等目的。

## 7. 能力矩阵（版本 × 通道）

| 能力 | Zotero 9 | Zotero 10 |
| --- | --- | --- |
| 读取（文库/PDF/批注/笔记） | ✅ 本地 API | ✅ 本地 API |
| 笔记、元数据、单条导入写入 | 既有 MCP 的兼容通道；未配置时只读 | ✅ 本地 API，无需额外 MCP |
| 普通高亮写入 | ❌（明确报错 + 建议升级） | ✅ 本地 API |
| AI 证据高亮 | ✅（审计链） | ✅（审计链） |
| 语义检索 | 取决于上游嵌入服务额度 | 同左 |

`workbench_status` 返回 `capabilities` 汇总；Agent 与面板据此决定能做什么，而不是先试后错。

## 8. 工具面（人机同面）

- Agent 可见：list_collections、search_library、get_item、open_item、show_items、read_fulltext、find_in_pdf、highlight（仅会话候选）、collect_evidence、research_query、review_evidence、prepare/commit_library_action、export_selection、inspect_item、render_reading_card、library_maintenance、workbench_status、cite、export_bib。
- 仅面板（app-only）：open_workbench、workbench_state、create_reader_highlight、save_reader_highlights。
- 命名规范：动词_宾语；领域前缀（reader / library / evidence）；禁止同名异义。
- 保存类操作的来源规则：`origin=user` 直接走网关；其余一律拒绝并指向审计链。

## 9. 数据流与隐私

- 本机：文库读取、PDF 分块（SHA-256 校验）、面板浏览。
- 明示外发：DOI/arXiv 识别（发编号给元数据服务）、语义检索（按上游服务）、用户点「提问/加入对话」（所选材料进入当前 Codex 对话）。
- 事务台账（~/.local/share/zotero-workbench/operations，600 权限）：只存操作散列、时间、条目/批注身份；不存论断全文、PDF 原文、凭证正文。
- 无新增云端、账号或统计。

## 10. 稳定性机制

读取：Total-Results 完备性校验、重叠页检测、版本变化丢弃、PDF 分块 SHA-256、SSE 帧界与大小上限、会话过期仅对只读请求重初始化。
写入：能力前置检查、指纹/版本/查重幂等、保留先于写入、回读核对、超时不重试。
已建故障注入：截断页、版本漂移、响应丢失、并发重复提交、诊断型预检拒写、超 500 条分页。待补：本地 API 写超时注入（Zotero 10 环境后）。

## 11. 测试策略（四层）

1. 离线契约：协议、分页、网关、模板、导出、事务语义（node --test，必须全绿）。
2. 故障注入：上述失败模式（离线）。
3. 真实联调：本机 Zotero 读取 + 受控写入（tests/live-sync.mjs，测试数据明确标注且可删）。
4. 宿主验收：Codex 正式侧栏真实操作；协议测试不能替代。

## 13. 差距与路线

- **P0（下一轮，机械执行）**：按 §5 拆分 server.mjs 到 transports/domain 模块；合并两处事务实例为单一网关；文档全部收敛到本文 + verification。
- **P1（功能补全）**：PDF 拖入与元数据识别；BibTeX/RIS 导入表单；图像批注与 TextBundle；语义检索额度恢复或多引擎；Zotero 10 升级后的写入验收（含超时注入）。
- **P2（商业化前置）**：PyMuPDF AGPL/商业许可决策或替换；干净环境安装复现；外部用户任务测试；分发许可审计。此前不宣称可销售。

## 14. 变更纪律（防混乱规则）

### 2026-10-29：吸收开源文献工具的可解释检查

沿用 Zotero 单一真值。借鉴 JabRef 的查重与逐项比较、Paperlib 的筛选入口，将 `duplicates` 加入现有信息检查。MCP、Codex 面板、DSH 共用一份候选识别函数：规范化 DOI 相同，或标题/年份/首位作者/类型相同且没有 DOI、版次、卷期、页码冲突。每条候选携带匹配理由、对方条目身份和原始字段差异。缺失作者/年份、过短标题不作标题匹配；同 DOI 的字段矛盾必须显式显示。只提供候选比较，不自动合并或删除。

扫描读取全部分页并绑定文库版本，续页携带版本；版本变化、页重叠、缺失总数均拒绝空成功。大库扫描及候选比较的上限须显式标记，不能称全库无重复。新增逻辑不持久化文献副本。完整调研与本轮采纳范围见 `github-design-review.md`。

1. 行为变更先改本文，再改代码；本文与代码不一致即为缺陷。
2. 新能力必须落到 §12 功能地图并给出测试证据，否则不得标记 ✅。
3. 补丁锚点失效时停止构建，禁止宽松匹配。
4. 每轮交付：构建 + 离线全绿 + 真实联调 + 明确的未验收清单。

## 15. 0.12.0：研究者标注优先与 TextFold

用户修正后的默认写作路线为：研究者选定的高亮/批注/子笔记 → 整理问题、分歧与边界 → 带摘录回链的初稿 → 人工核对。不得先生成论断再搜原文补高亮。既有审计工具保留用于明确要求的引用核查，不作为成文前置，也不自动创建 AI 高亮。

两条独立流程共用笔记与写作页面：
- 标注汇总按指定文献或分类（含子分类）分页读取。原文摘录、阅读者备注和独立笔记分开；不按颜色推断作者。用户勾选形成明确语料范围。生成前重新读取并校验材料版本，只发送选中内容。每段回链必须属于所选材料；无法支持的内容列为缺口。语义是否成立由人核对。
- TextFold 按单篇 PDF 一键启动后台任务。先提取所有页，AI 通读全文建立整体理解，再用固定的 TextFold 0.10.40 解析、层级生成与导出代码逐页折叠。禁止用摘要或首句降级冒充 AI 全文完成。保留 PDF 指纹和页码；源文件变化、漏页、模型失败、局部降级时明确失败。五层展示区别原文/原句与 AI 概括。图表、扫描页 OCR 缺失时不能自称读完。

后台 AI 使用本机已登录 Codex CLI 的配置，不需要用户在聊天里重述任务；DSH 与 Codex 共用任务服务和界面逻辑。进度、取消、重载恢复与错误可见。默认一次最多两项任务；全文最多 200 页且 16 万字符，超限明确拒绝而非静默截断。派生结果以私有文件保存在本机研究缓存，不回写 Zotero，也不形成独立权威文库。

视觉采用用户提供的 Files 参考：白底、暖灰细线、清楚的正文层级、小圆角、紧凑列表与可收起的详情。复用现有框架和主题，不为参考页更换整个技术栈。

### 0.12.0 补充设计：功能保留与控件语义

主代理负责设计、范围与验收；具体开发由用户指定的 GPT-6 Luna 子代理执行（当前接口没有 GPT-6 Terra，用户已改选 Luna）。

新版必须保留已可用的文库分类/搜索/多选、条目摘要/注释/元数据/附件/标签、PDF 缩放/跳页/真实高亮/批注浮层/在 Zotero 中显示、提问/加入对话、导入/导出/期刊等级/重复检查。界面简化不等于删除能力。引用核查和补充检索只保留为主动使用的辅助入口，不再决定默认写作路线。验收分别记录代码接线、协议测试与真实界面表现，不能互相替代。

| 控件 | 含义与外观 | 交互约束 |
| --- | --- | --- |
| Badge 徽标 | 状态、数量、PDF 类型、期刊收录；小号字、紧凑圆角矩形、低饱和底色 | 默认不可点击；状态不能只靠颜色 |
| Chip 选择碎片 | 已选文献或筛选条件；文本加移除按钮 | 可移除，显示清楚焦点与移除名称；不能拿来表示普通主题 |
| Pill 胶囊切换 | 单选模式、TextFold 阅读层级；连续分段切换 | 有唯一选中态、键盘焦点和可访问状态；不做装饰性满屏胶囊 |
| Tag 标签 | Zotero 主题与分类；标签/文件夹图标、浅描边、小圆角 | 描述分类身份；若支持筛选，按钮行为需明确，不出现伪关闭符号 |

### 批注恢复事务约束

仅对本机台账中已核实移入回收站的操作提供恢复预览。预览必须从 Zotero 官方 Trash 列表找到唯一原批注 key，校验删除后保存的批注版本、原 PDF 附件身份和版本；明确确认后只对该 key 发送带 `If-Unmodified-Since-Version` 的 `PATCH {deleted:false}`，不得创建替代批注。成功须回读确认原 key 不在 Trash、仍在普通文库且未标为删除。操作编号、版本与状态写入私有本机台账；结果未知时禁止重试，只能通过 `review_operation` 核查。持久化最近一次已核实删除的操作编号，供跨会话恢复入口读取。恢复入口可用、模拟测试通过与真实 Zotero 恢复通过是三种不同状态；未经专用测试数据和正式宿主回读不得宣称真实恢复已验收。

## 1.2 研究阅读增量

ResearchWorkspace继续只读Zotero来源，并管理私有派生任务。翻译由纯Node translation-worker调用已配置Codex CLI，TextFold保留锁定的Python解析与五层引擎。research-model-config集中读取可选后台阅读模型；不改全局模型、服务或账号。译文按原文指纹/目标语言/算法版本缓存，并以本次真实读取重绑来源；恢复时重新核验，离线不毁掉成功快照。

研究视图共享于Codex/DSH，分组不改变材料身份。勾选只保存id和fingerprint，重新读取后才恢复；自动翻译与研究导读不自动变成人工写作语料。原文/批注/备注/笔记/机器译文的显示边界与来源记录相互独立。

## 1.2.2 元数据双语

translate_metadata是ResearchWorkspace的只读元数据任务，直接重读当前Zotero条目的title/abstractNote/language，不进入PDF提取或写入通道。字段按共同纯文本规则显示，单独判定是否外文，译文按原文字段缓存；结果保留两字段原文、译文、可用状态、身份和来源指纹，恢复前再次核验。Codex列表与详情共享进行中任务，未知摘要不当作空摘要清除缓存；DSH沿用同一模型任务与结果契约。机器译文只作阅读辅助，不自动加入人工写作来源。
