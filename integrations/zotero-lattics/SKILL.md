# Zotero—Lattics 引用证据工作流

## 入口选择

- 从正文找证据：按下述原有流程执行。
- 从已有高亮批注组织综述与引用：先完整读取 [批注到写作](references/annotation_to_writing.md)，再按本 Skill 的来源理解、逐原子对齐和风险规则评估拟采用内容。先汇总指定分类，再组织主题、提出落点；无需用户记住每条材料出自哪篇。
- 已有批注的导航与材料整理保持只读；正式引用仍须语义审计。复用真实 annotation 不创建重复高亮。没有指定分类或论文时，只补齐必要输入，不扫描整个库或擅改稿。

## 目标与边界

形成可追溯证据链：

```text
论文语境 → 当前论证卡 → 候选召回 → 论文理解卡
→ Source-first 来源命题 → 逐原子对齐 → 缺失前提检查
→ 风险分流与主动修复 → 语义许可 → PDF定位与dry-run
→ Zotero待核查高亮 → Markdown回链 → 用户终审 → Lattics
```

- Zotero 条目、实际 PDF、真实页码、原文和 annotation 是证据真值源。
- 关键词、向量分数、摘要相似、旧高亮、页码正确和链接有效都不证明引用成立。
- 合理支撑不要求研究完全同构，但不得凭桥接新增行动者、关系、结果变量、时间顺序、机制或因果强度。
- 用户负责最终学术采用；Agent 负责在交付前认真理解、核查和主动修复，不能把明显可解决的问题直接甩给用户。

## 一、先理解正文在论证什么

每次核查先读当前句、完整段落、上下各一段和小节标题；已有论文论证地图时只加载相关节点。生成简短论证卡：

- 本段回答什么问题，当前句承担什么作用；
- `citation_scope`：引用具体覆盖哪个从句、数字或关系；
- `source_core`：来源必须承担的命题；
- `author_synthesis`：作者综合或本文命题，不能伪装成来源原结论；
- 需要的证据角色：定义、理论命题、作者实证结果、政策事实、数据或综述；
- 主体、关系、方向、强度、结果、层级、范围、条件。
- `risk_flags` 与 `route_reason`：按第七节的明确条件记录为何选择 FAST、STANDARD 或 STRICT。

复合句先拆成原子。每个原子只允许一个核心主体—关系—结果；“以及”“并且”“不仅……也”“通过……进而”等造成多个关系时必须拆分。拆不开则为 `U`，不得写入。

## 二、论文理解卡：按需建立、以后复用

研究任务的阅读基础存到对应项目，不能默认放在某个 Agent 私有目录。先读项目 README/PATH，检查根目录 `.zotero-lattics.json`；已有登记直接 `list-papers` 查重。首次使用优先选既有文献资料目录下的 `Zotero阅读缓存`，没有合适目录才用项目根下 `Zotero文献缓存`，以 `init-project` 登记相对路径并在既有项目入口补一条位置说明。不要把 vault 根或当前 Skill 工程误当论文项目；项目不明先问归属。详细命令见 [原文读取与复用](references/fulltext_reading.md)。

不同 Agent 共用完整原文、页/块映射、来源理解卡、实际阅读范围与未解决问题。理解卡通过 `save-reading` 保存不可覆盖的独立快照，默认是 AI 未经人工确认的阅读记录；接手时查看同一 PDF 指纹下的记录，回查相关原文后续读，不因已有卡片就重读全部，也不继承“这条引用已经合格”。旧全局缓存不自动迁移；本轮引用的判断包与定位/回链结果留在该项目本次工作记录中。

不要预处理整个 Zotero 库。候选首次进入高价值范围时建立 `L1` 摘要初筛卡：研究问题、对象、层级、时空、核心关系、设计、主要结论和证据角色；摘要没有提到的内容只能记为“未检查”，不能据此断言全文不存在。

正式采用前升级 `L2`：普通论文首次使用先按结构分批阅读完整正文；长篇报告/书籍读导言、结论和完整相关章节，并注明未读范围。不要把全部 PDF 一次塞进上下文。使用 [原文读取与复用](references/fulltext_reading.md) 中的本地阅读器，保留带物理页码与原文块映射的 Markdown 阅读副本、完整原文 JSON 和 PDF SHA-256；只读过摘要或检索片段时不得标记全文已读。

卡片绑定 `parentItemKey + attachmentKey + PDF fingerprint`；PDF 改变即失效。卡片用于筛选和定向阅读，不能替代本次引用的原文回读。详细字段见 [证据协议 v2](references/evidence_protocol_v2.md)。

同文献的全文提取、来源理解只做一次，供多处引用复用；每处支持性重新判断。缓存可用、原文送达、模型理解和用户确认分别记录。扫描/错列/表格问题回查原页，不把自动抽取当作可靠全文。

## 三、召回只负责减少阅读量

1. 已指定引文先直接锁定，不做多余全库召回。寻找替代来源时先用已有论文卡筛选，再用题名/作者、全文词面、同义表达和 `semantic_search` 混合召回；只调用当前确实提供的工具，不假定存在 BM25。
2. 每个原子生成主体、关系、结果、机制、限定和反向查询；跨语言论文使用原语言查询。
3. 摘要筛查研究问题、对象、层级、方法、主要结果和边界；明显主题错配排除。理论引用允许研究场景差异，不要求完全同构；摘要沉默不能作为全文缺失证明。
4. 默认保留少量最有希望的候选；找到充分证据后停止，不机械凑满数量。
5. 语义得分只决定先读什么，永远不能进入证据等级计算。

## 四、Source-first：先固定来源原意

检索可以看到正文论断。独立来源阅读者使用不继承完整对话的新上下文，只给文献身份、全文阅读入口和中性主题，不给目标结论或主 Agent 的判断。不能只交筛出的短句；按第二节读取全文/完整相关章节。无法隔离时如实标记“同一上下文先读后判”，不得声称独立盲审。

来源阅读者必须输出：

- 作者实际提出或发现的命题；
- 主体、关系、结果、方向、强度、层级和范围；
- 证据角色：作者实证、作者理论、二手转述、讨论、推测或政策文本；
- 重要限定、否定、异质性和研究边界；
- `explicitly_not_established`：该文或该段明确没有证明什么；
- 支撑来源命题的连续原文和必要上下文。

短高亮可以是一个完整句子，但裁决不得只读孤立小句。理解全文后回读候选完整段落及前后段；代词、转折、表格、样本、机制或限定不清时读到完整相关小节/方法/结果，不设机械的两轮上限。取得必要内容仍无法判断才为 `U`，说明具体缺口。

## 五、Claim—Source 对齐与缺失前提

来源命题固定后，再与正文原子逐项比较：主体、关系、结果、方向、强度、层级、范围和证据角色。每项只能是：

- `MATCH`
- `ACCEPTABLE_TRANSFER`
- `REQUIRES_BRIDGE`
- `MISMATCH`
- `CONFLICT`
- `UNKNOWN`

随后回答：从来源命题到正文原子还需要加入哪些原文没有提供的前提？将前提标为同义等价、范围迁移、理论桥接、新经验命题、新行动者、新结果、新机制、新时间顺序或因果升级。

允许直接跨越同义改写、正常概括、明确范围收窄和原文已蕴含的关系。新行动者、新结果、新机制、新时间顺序和因果升级不能由当前来源补出。多篇文献各沾一点不能共同获得 `FULL`；每篇只对分配给它的原子负责。

## 六、证据等级

| 等级 | 含义 | 动作 |
| --- | --- | --- |
| `S3` | 核心命题可由来源直接恢复 | 可进入定位、高亮和回链 |
| `S2` | 核心关系、方向和结果一致，仅有已说明的有限迁移 | 升级 STRICT 并通过独立反方审查后可写入 |
| `S1` | 只覆盖部分原子、强度过高或仍需桥接 | 拆句、收紧、补证或换来源；不得写入 |
| `R` | 主题相关但当前关系或结果不存在 | 继续检索；不得写入 |
| `X` | 方向、结果状态或重要限定与正文冲突 | 撤换或改写 |
| `U` | 全文、语境、版本或裁决不足 | 补材料后重审 |

等级由审计脚本根据模型填写的逐项对齐、缺失前提、风险和挑战者检查推导。脚本只检查结构与逻辑一致性，不理解文献；错误填写 MATCH 仍可能得到 S3，不能把脚本通过称为语义已验证。主 Agent 不得在 v2 判断包中填写 `FULL`、`PASSED`、`S3` 或 `eligible=true`。

## 七、按风险控制成本

### FAST

仅用于：单一原子、已理解文献、同层级、单连续片段、无迁移、非因果/机制/政策/统计/异质性。单 Agent 完成，只有全维度 `MATCH` 才能得到 `S3`。

### STANDARD

默认路线。用于普通定义、描述事实、直接经验关系，以及有限对象或时空差异、多原子、多片段、代理测量。必须执行缺失前提和八项反向检查；出现可接受迁移时升级 STRICT 后才能取得 `S2`。候选文献彼此独立且协作工具可用时，可并行进行只读 Source-first；Source Reader 返回后由主 Agent 串行完成 `topic_relevance`、`claim_support`、逐维对齐和 H1—H8，再交脚本统一裁决。

### STRICT

用于：因果、机制、中介、调节、精确数字、政策效果、跨层级、二手转述、异质性、无显著、多个来源联合、`S2` 或挑战者提出重大异议。使用隔离的来源阅读、主张判断和反方审查；必要时再由仲裁者裁决。

不按预设比例硬分流。简单引用找到充分证据即停；复杂引用允许更慢。

## 八、多 Agent 并行协议

协作工具可用、至少有两篇独立候选且并行能实质缩短阅读时间时，STANDARD/STRICT 允许并行。FAST 不启动子 Agent。默认同时最多两个 Source Reader；找到充分证据后取消或不再启动其余候选。

1. 主 Agent 读取论文语境、拆原子、分配候选和最终整合，但不自行签发合格等级。
2. STANDARD 只允许 Source Reader 按文献并行，不启动多重裁判；主 Agent 在来源命题固定后串行完成 `topic_relevance`、`claim_support`、逐维对齐和 H1—H8。回执映射成 STRICT 只是现有 MCP 的传输兼容，不会把 STANDARD 变成多裁判流程。
3. STRICT 中，多篇候选的 Source Reader 可并行；来源命题返回后，Claim Judge 与 Challenger 可并行：前者逐原子对齐并列缺失前提，后者专查八类硬伤。
4. Claim Judge 必须把 `topic_relevance` 与 `claim_support` 分开报告，不能以主题相关代替支持。仅在 Judge 与 Challenger 冲突且影响写入资格时启动 Arbiter；Arbiter 只返回冲突原子、双方依据、建议裁决、剩余缺口和能否进入审计脚本，不得给出 `S3` 或 `eligible=true`。
5. 子 Agent 对 Zotero 和论文保持只读，不得高亮、改稿或签发最终许可；允许在已分配的项目缓存内保存原文和独立阅读记录，不覆盖其他 Agent 的记录。主 Agent只在用户已授权且审计脚本通过后写入 Zotero。
6. 每个子任务必须携带明确的条目 key、附件 key、原文范围、输出结构和停止条件；不得让子 Agent无边界搜索整个库。

按文献分工，同篇多处引用共用一名来源阅读者；Judge/Challenger 必须同时取得原始上下文与全文阅读入口，不可只依据阅读者摘要裁决。多 Agent 一致不构成准确性证明。

角色输入输出和降级策略见 [多 Agent 协议](references/multi_agent_protocol.md)。

## 九、主动修复与停止条件

未达到 `S3/S2` 时依次：同文献重找 → 检查同句其他引用 → Zotero 全库 → 外部同行评议或权威原文 → 报告最强候选和缺口。外部候选经用户确认并导入 Zotero 后重新走完整流程。

找不到强证据时优先选择：拆句、收紧范围、降低因果强度、补桥接文献或明确写成作者推断。不得用 `R/S1` 凑引用。

## 十、Ricky zotero MCP 对接

- 父条目 key：文献身份、摘要、限定语义检索和全文读取。
- PDF 附件 key：定位、高亮和 `zotero://open-pdf`。
- `semantic_search` 锁定文献后必须传父条目 `itemKeys`。
- 当前语义检索返回有限片段，只作导航；返回少、无命中或跨语言漏召回时转全文读取，不能推断无证据。使用原文语言补查。
- MCP `get_content` 必须显式选择 `mode="complete"`；默认标准输出可能截断。完整 PDF 优先用本地阅读器分批读取，核对工具外层输出也没有截断。
- `get_annotations.text` 是高亮原文，`comment` 只是备注。
- 多 PDF 版本、扫描件、重复命中、弱定位或 PDF 变化时停止写入。

审计脚本：

```bash
python3 scripts/citation_evidence_audit.py issue judgment-v2.json
python3 scripts/citation_evidence_audit.py preflight-bind judgment-v2.json receipt.json locators.json
```

`issue` 只签发 v2；旧 v1 只能用显式的 `issue-legacy-v1` 迁移入口。判断包格式见 [证据协议 v2](references/evidence_protocol_v2.md)。当前脚本输出与已安装 MCP 兼容的 `audit_receipt_version=1`，同时标记 `semantic_protocol_version=2`；工作流中的 `STANDARD` 会以更严格的 `STRICT` 线协议传给 MCP，并保留 `semantic_route=STANDARD` 供审计，不得手工编辑输出。

v2 调用 `create_review_highlight` 前必须先运行 `preflight-bind` 并得到 `valid=true`；禁止绕过它直接提交回执。已安装的 MCP 1.7.1 负责 v1 线格式、PDF 与写入校验，尚不原生重推导 v2 的结构化语义判断，这一重推导当前由审计脚本和 preflight 承担。

每个通过审计的片段使用 `scripts/locate_pdf_text.py` 定位。定位器的 `--text` 必须直接取自判断包对应 `fragment.source_text`，禁止重新摘录或改标点。

调用 `create_review_highlight` 时，`locatorResults` 和 `auditReceipt` 都传未改动的 JSON 字符串。先 `dryRun=true`；用户在同一请求明确要求高亮后，才以同一组凭证执行 `dryRun=false, confirmWrite=true`。

## 十一、回链与 Lattics

使用 `scripts/zotero_markdown_links.py` 预演、写入和扫描。链接只挂在该来源实际承担的从句或作者—年份上。`invalid_count=0` 只证明链接结构有效。

Lattics 中关闭“自动生成卡片”才能保留蓝色 Zotero 回链。用户点击回链回读所有必要高亮，再从 Zotero 复制真实摘录到 Lattics。

## 十二、完成报告

至少报告：正文引用责任、来源实际命题、缺失前提、逐原子等级、摘要/上下文读取范围、修复动作、当前状态和用户终审入口。只有语义许可、全部必要定位凭证、真实 annotation 和可点击深链同时存在，才可写“高亮与回链已完成”。
