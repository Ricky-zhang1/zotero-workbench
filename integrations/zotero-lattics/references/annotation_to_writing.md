# 从批注组织综述与引用

## 任务与权限

让用户只负责阅读与标注，Agent 负责找回来源、理解、组织与匹配。适用于所有论文，不依赖特定稿件。用户不必统一颜色、提前打标签或记住文献名。

默认交付主题组织、综述框架和引用建议，不修改论文、Zotero 或 Lattics。用户明确要求写草稿时可生成独立草稿；明确要求插入/修改指定论文时才改稿。仅“看看怎么用”不授权替换原文。读取范围和输出归属优先从上下文确定，缺少实质信息才询问。

## 1. 锁定分类并完整取得批注

1. 用当前实际工具的集合查询接口解析分类名，记录 libraryID、collectionKey 和完整分类路径。同名而无法唯一确定时先问。默认包含子分类，并在范围说明中写清；用户指定“仅当前分类”则排除子分类。
2. 用 `get_subcollections(recursive=true)` 取得后代分类；用 `get_collection_items(collectionKey, libraryID, limit, offset)` 分页读取每个分类。按 libraryID + 文献 key 去重，保留多分类归属。读取条目元数据及附件关系，分清父文献、PDF 附件和批注。
3. 用 `get_annotations` 读取相关文献/附件的批注，显式选择 `mode="complete"`，依接口结果用 limit/offset 续页；检查正文是否被 maxTokens 或工具外层截断。依据实际返回核对 itemKey 指向及附件覆盖，不假定父条目调用自动包含所有 PDF。多个附件保留版本身份，不混拼。
4. 收齐指定范围，而非只取与拟写主题相似的批注。逐页处理，保留进度；没有总数时按接口分页终止语义遍历，不能凭首批或一次空响应宣称全部完成。错误/截断与确实零条分开报告。大量批注分批读入，不把整个集合一次塞进上下文。
5. 记录原文 text、个人 comment、批注类型、颜色/标签、annotation key、attachment key、父文献 key、libraryID、物理页/显示页标签及可用修改时间。身份缺失时先补读，禁止猜 key 或把印刷页直接当物理页。去重按 libraryID + annotation key；相同文字但不同来源/位置保留各自身份。

现有 MCP 接口名称以当次发现的 schema 为准；没有真实批量接口就按条目分批调用，不能假造“一键读取集合批注”接口。首轮低并发读取，确认稳定后再适度并发；复用元数据和已取结果，不因失败重新读取整个分类。

## 2. 分清原文、阅读者想法与批注来源

- text 是摘录，comment 是阅读者的解释/问题/提醒；个人看法不能伪装成原作者结论。高亮只表明被注意，可能是疑问、反例或作者转述别人。
- 优先用已有任务记录、明确标记、批注 ID 对照表识别 AI 创建的待核查材料。颜色不能证明作者身份；无法区分时标记“来源未确认”，单列而非丢弃，也不称为用户亲自确认。
- 注释型、图片型、手写型或无可提取文本的批注保留入口；需要时查看对应 PDF 页面。不得把 OCR 猜测或图像描述冒充逐字原文。
- 用户的全部高亮只代表个人阅读样本，不代表领域全部研究。未高亮不说明原文没有相关结论；不得据此宣称研究空白或系统综述穷尽。

## 3. 先理解来源，再组织综述

先按文献聚合批注和个人评论，读摘要建立 L1 来源理解，恢复研究问题、主要发现和限定。摘要缺失时读 PDF 对应内容，不凭题名推断。关联片段回读完整段落及前后语境；否定、转折、代词、二手转述、表格解释不清时扩展阅读。保留矛盾与保留意见，不只挑支持预设结论的片段。

初步材料地图可基于批注、摘要和必要上下文，但必须标明“初筛，未正式采用”。拟进入成稿的来源按主 Skill 第二节升级 L2，读取完整正文/完整相关章节；已有同指纹阅读卡可以复用基础，回读本次引用的相关原文。不能把批注汇总写成“全文已经读过”。

用语义理解聚合研究问题、解释关系、理论分歧、适用条件和方法差异，允许同义改写与跨语言概括；不要按几个共同词或作者名单机械分组。每个主题给出一个可展开的论述中心、互补/冲突来源、边界及尚缺的证据。跨文献综合属于作者综合，不能让其中一篇承担整个综合命题。

已知批注位置直接读上下文，不为重新找到它再跑语义检索。仅在上下文不足、主题缺证或寻找替代来源时，按主 Skill 使用限定文献/集合候选的语义召回，必要时扩展 Zotero 全库和外部原文；新增候选不得混称为用户已读材料。

## 4. 有论文时，双向匹配引用位置

先理解论文研究问题、主线和章节分工；逐节读取相关正文，给建议引用位置保留句段定位。没有论文时输出综述组织方案，不捏造正文位置。

对每条拟采用材料，先固定来源实际命题，再判断哪个具体论断可由它承担。反向检查论文已有引用/重复论证，区分补充证据、定义概念、呈现争论、限定原句和提出反例。可以建议新段落，但不得为安置高亮而改变论文问题或硬加观点。

按主 Skill 的对齐、缺失前提、风险路线及审计脚本评估。合理概括/有限迁移无需研究完全同构；主题相关、评论感想或个别同词不能获得正式引用资格。材料确实不适合当前论文时保留在主题资料里，不强行安插。证据不足的落点主动补证；外部文献经用户核实并导入 Zotero 后再定位和正式引用。

## 5. 复用已有高亮并生成回链

材料清单可提供“阅读入口”链接，这仅为导航，不表示支持性合格。正式成稿的引用链接须在语义审计通过后，回读确认 annotation 真实存在、归属附件、对应原文及物理位置，检查 PDF 版本。不能只扫描 URL 就宣称核验完成。

复用已有 annotation 无须调用 `create_review_highlight`，不重复高亮、不改颜色/评论、不借此绕过语义判断。若旧高亮仅覆盖几个字，先提供上下文与缺口；需要扩大高亮时由用户授权，再走原有定位、preflight-bind、dry-run 和写入链路。链接拼接、库类型及编码遵循现有回链工具，不臆造 group/user library 路径。

分散证据各保留真实片段与回链，禁止拼成连续引语；正文可以挂第一个入口，证据说明列出所有必要位置。全文主旨型概述需实际读过正文，摘要可作入口，但不能用摘要代替审查正文。Lattics 交接沿用既有流程；Markdown 导航链接不能冒称已生成原生文献引用对象。

## 6. 输出、复用与完成标准

最小交付按任务选择，不机械生成所有文件：

- 材料组织：主题 → 可展开的观点/争论 → 来源与真实摘录入口 → 适用边界。
- 论文引用建议：论文句段 → 拟支撑的命题 → 来源实际含义/必要片段 → 支持判断与理由 → 建议插入或改写 → 回链。
- 简短收据：分类及子分类范围、去重文献数、有批注文献数、批注数、未完整读取/身份不明项，以及哪些仅初筛、哪些已核查。数量从实际结果计算，不编造完成率。

用户未指定论文时，先完成材料组织即可。按需给少量经过核查的示范段落，避免堆满引文表却不说明如何论述。

结果放对应研究项目既有文献/写作目录，沿用项目阅读缓存，不建全局第二套库。续跑按条目/批注 ID 对比内容、归属和修改信息；无可靠版本字段时重新取得并对比，不宣称安全增量。批注删除、改动、附件变更或 PDF 指纹变化时复核受影响材料；来源阅读可以复用，但换论文论断仍需重新匹配。维护一次运行的读取进度，失败仅续未完成部分。

自然语言示例：

- “读取 Zotero 的‘教师流动’分类及子分类，把我的高亮组织成文献综述思路。”
- “把这个分类里的批注和我的论文对照，告诉我适合用在哪些段落，先不要改正文。”
- “按核查通过的建议插入引用，保留原来的高亮和回链。”
